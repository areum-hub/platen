# Platen — 종이와 잉크

밤 램프 아래 타자기로 쓰는 메모. 기능은 평범한 노트지만, 종이 질감·타자 소리·따라오는 램프 불빛으로 **쓰는 경험**에 아날로그 감성을 더했다.

- 운영 사이트: **https://memo.dante-labs.com**
- 파일 하나: `index.html` (빌드 없음, 서버 없음)
- 자판 위치대로 한글이 찍힌다. 한/영 상태를 바꿀 필요가 없다.

## 자동 타이핑 몰입 타이머 

### 만든 이유

PLATEN은 아날로그 타자기 경험을 제공하는 웹 애플리케이션으로, 자동 타이핑을 통해 글자가 종이 위에 한 자씩 입력되는 과정을 경험할 수 있습니다.

기존 자동 타이핑 기능은 글이 입력되는 과정을 보여주지만, 사용자가 원하는 시간만큼 실행하거나 중간에 멈추고 다시 이어가는 데에는 한계가 있었습니다. 또한 집중 시간을 관리하려면 별도의 타이머를 사용해야 하므로 이용 흐름이 분리되는 문제가 있었습니다.

이를 개선하기 위해 자동 타이핑과 집중 타이머를 연동하는 몰입 타이머 기능을 추가했습니다.

사용자가 5분 또는 10분의 집중 시간을 선택하면 타이머와 자동 타이핑이 함께 실행되며, 일시정지와 재개도 동일하게 적용됩니다. 시간이 종료되면 자동 타이핑이 정지하고, 초기화하더라도 기존에 입력된 글은 유지됩니다.

이를 통해 별도의 시간 관리 도구 없이 하나의 화면에서 자동 타이핑과 집중 시간을 함께 제어할 수 있는 환경을 구현하고자 했습니다.

### 핵심 기능 3가지

**1. 5분·10분 몰입 시간 선택**

하단의 `5분` / `10분` 버튼으로 감상할 시간을 고릅니다. 고른 시간이 곧 화면의 카운트다운 시작값이 되고, 시작을 누르면 그 시간만큼 자동 타이핑이 흘러갑니다. 기본값은 5분입니다.

**2. 시작·일시정지·초기화로 자동 타이핑까지 함께 제어**

버튼 하나로 타이머와 자동 타이핑이 동시에 움직입니다. 잠깐 자리를 비우고 싶으면 일시정지, 처음부터 다시 보고 싶으면 초기화입니다. 초기화는 글을 지우지 않으므로 쓰던 내용은 그대로 남습니다.

**3. 종료 알림과 시간 오차 방지**

시간이 다 되면 알림음이 울리고 탭 제목이 `집중 종료` 로 바뀝니다. 남은 시간은 매번 다시 계산하지 않고 **끝나는 시각을 기준으로 계산**해서, 탭이 느려지거나 백그라운드에 있어도 시간이 밀리지 않습니다.

### 기존 기능은 그대로입니다

타이핑과 한글 자모 조합, 램프 슬라이더 세 개, 램프 켜고 끄기, 자동 타이핑, 리셋, 타자 소리, 글꼴 선택, 글자 크기, 잉크 효과, 자동 저장·복원, 설정 기억하기, `.txt` 다운로드가 모두 그대로 동작합니다.

## 실행 방법 (Windows)

**1. GitHub 저장소 복제**

PowerShell 또는 VS Code 터미널을 열고 다음 명령어를 실행합니다.

```powershell
git clone https://github.com/areum-hub/platen.git
cd platen
```

**2. 로컬 서버 실행**

Python을 사용하여 로컬 서버를 실행합니다.

```powershell
python -m http.server 8000
```

Python 명령어가 실행되지 않으면 다음 명령어를 사용합니다.

```powershell
py -m http.server 8000
```

**3. 브라우저에서 실행**

Chrome 또는 Edge에서 다음 주소로 접속합니다.

http://localhost:8000/index.html

또는 PowerShell에서 아래 명령어로 브라우저를 실행할 수 있습니다.

```powershell
Start-Process "http://localhost:8000/index.html"
```

**4. 서버 종료**

PowerShell에서 `Ctrl + C`를 누르면 로컬 서버가 종료됩니다.

## Hermes 와 함께한 작업 기록

이 기능은 Hermes(개발용 프로필)와 대화하면서 만들었습니다. 무엇을 요청했고, 무엇이 문제였고, 어떻게 풀었는지 순서대로 적습니다.

### 1. 요청

- "자동 타이핑에 몰입할 수 있는 타이머를 넣고 싶다. 5분·10분 중에 고를 수 있게."
- "기존 기능은 하나도 깨지면 안 된다."
- "내 저장소 `main` 에 반영할 수 있게 준비해 달라."

### 2. 구현

- `index.html` 한 파일 안에서만 작업했습니다. CSS 는 `<style>` 에, 마크업은 하단 안내 줄 위에, 동작은 `<script>` 끝부분에 모았습니다.
- 기존 변수·함수 이름과 겹치지 않도록 `focus*` 접두사를 붙였습니다.
- 자동 타이핑의 기존 함수(`startDemo` / `stopDemo` / `isDemoRunning`)를 **그대로 호출**해서, 타이핑 로직을 새로 만들지 않았습니다.

### 3. 사용자 검증

브라우저에서 직접 눌러 확인한 항목입니다.

| 동작 | 확인한 결과 |
| --- | --- |
| 시작 | 05:00 → 04:59 로 줄고, 자동 타이핑이 시작됨 |
| 일시정지 | 숫자가 멈추고 타이핑도 멈춤. 시계가 노란색이 됨 |
| 다시 시작 | 남은 시간부터 이어지고 타이핑 재개 |
| 초기화 | 05:00 으로 돌아가고 쓰던 글은 그대로 남음 |
| 10분 선택 | 10:00 으로 표시가 바뀜 |
| 시간 종료 | 00:00, 알림음, 탭 제목이 `집중 종료 ` 로 바뀜 |

### 4. 오류 해결

작업 중 실제로 만난 문제를 일어난 순서대로 적습니다. 원인과 고친 방법을 함께 적었습니다.

#### 코드 문제

**(1) 원본 PR 에 `</style>` 이 두 번 들어 있어 하단 안내 줄이 글자로 보임**

원본 브랜치의 `index.html` 은 스타일시트 중간에 `</style>` 이 하나 더 있었습니다. 그 뒤에 오는 `.footer-hint` 규칙은 CSS 로 해석되지 않고 페이지 본문 글자로 출력됐습니다. 추가된 닫는 태그를 지워 스타일시트를 하나로 되돌렸습니다.

**(2) 5분을 골랐는데 화면에 10:00 이 표시됨**

남은 시간의 초기값이 10분으로 고정돼 있어서, `5분` 이 선택된 상태인데도 10:00 이 보였습니다. 초기값을 "지금 선택된 버튼의 시간"으로 계산하도록 바꿔 05:00 과 맞췄습니다.

**(3) 초기화를 눌러도 자동 타이핑이 계속 돌아감**

초기화 함수가 상태를 먼저 `false` 로 바꾼 뒤에 "돌고 있었으면 멈춘다"를 검사했습니다. 순서가 반대라 조건이 항상 거짓이 됐습니다. 검사할 값을 먼저 변수에 담아 두고 상태를 바꾸도록 순서를 고쳤습니다.

**(4) 타이머 패널이 종이 영역을 115px 나 밀어냄**

처음 만든 패널은 세로로 쌓인 카드 모양이라 종이 자리를 크게 잡아먹었습니다. PLATEN 은 종이가 화면의 핵심이라 이건 받아들일 수 없었습니다. 한 줄짜리 가로 바로 바꿔 38px 만 쓰게 했습니다. 종이 높이는 330px 에서 292px 로 줄었고, 창 높이를 480px 로 줄여도 하단 안내 줄이 잘리지 않는 것을 확인했습니다.

**(5) 타이머 버튼을 누르면 자동 타이핑이 즉시 멈춤**

타이머 패널이 종이 영역(`paperViewport`) 안에 있었습니다. 버튼 클릭이 종이 클릭으로 전파되면서 `stopDemo()` 가 함께 실행됐습니다. 패널에서 클릭 전파를 막아 해결했습니다.

**(6) 재개했는데 시계는 가는데 글자가 안 늘어남**

일시정지 후 다시 시작했을 때 시계는 이어지는데 글자 수가 그대로인 경우가 있었습니다. 원인을 확인해 보니 버그가 아니었습니다. 자동 타이핑 문구가 94자로 정해져 있는데, 이미 끝까지 찍힌 상태였습니다. 이어서 찍을 내용이 없으니 글자가 늘지 않는 것이 정상입니다. 시계는 정상적으로 이어집니다. 

#### 저장소·배포 문제

**(7) 원본 PR 을 그대로 병합하면 최근 기능이 사라질 상태였음**

원본 PR #51 의 브랜치는 최신 `main` 보다 오래된 지점에서 갈라져 있었습니다. 그대로 병합하면 그사이 병합된 기능 7건(자동 저장·복원, 설정 기억, 키보드 버튼, TXT 다운로드, 리셋 버그 수정, 상단 페이드, 자모 조합 수정)이 사라집니다. 그래서 최신 `main` 위에 새 브랜치를 만들어 타이머 기능만 다시 얹었습니다. 기존 코드는 한 줄도 지우지 않았습니다(추가 260줄, 삭제 0줄). 작업이 끝난 브랜치는 병합 후 정리했습니다.

**(8) fork 에 Pages 를 켜면 원본 운영 사이트와 주소가 충돌할 뻔함**

fork 에는 원본의 `CNAME`(`memo.dante-labs.com`)이 그대로 남아 있었습니다. 이 상태로 Pages 를 켜면 GitHub 이 이 fork 를 그 도메인에 연결하려 합니다. 그 도메인의 DNS 는 원본(`dandacompany.github.io`)을 가리키므로 원본 사이트에 영향이 갈 수 있었습니다. 순서를 지켜 해결했습니다. 먼저 `CNAME` 을 지우는 변경을 `main` 에 병합하고, 그다음 Pages 를 켰습니다. 배포 워크플로 주석에도 "fork 에서는 CNAME 을 쓰지 않는다"는 주의를 남겼습니다. 결과적으로 데모는 `https://areum-hub.github.io/platen/` 로 열리고, 원본 사이트는 그대로 200 으로 살아 있습니다.

**(9) README 만 고친 커밋은 사이트에 반영되지 않음**

문서만 바꾼 커밋에서는 배포 워크플로가 자동으로 실행되지 않았습니다. 사이트가 이전 `main` 에 머물러 있었습니다. `workflow_dispatch` 로 `Deploy to GitHub Pages` 를 직접 실행해 사이트를 최신 `main` 과 맞췄습니다. 앞으로도 문서만 고칠 때는 Actions 탭에서 같은 워크플로를 수동 실행하면 됩니다.

**(10) 오래된 배포 기록이 삭제되지 않음 (422 Validation Failed)**

배포 이력을 최신 한 건만 남기려 했더니 GitHub 이 `422 Validation Failed` 로 거부했습니다. 이유는 "활성 배포는 그 환경의 유일한 배포일 때만 삭제할 수 있다"였습니다. 오래된 배포를 먼저 `inactive` 상태로 바꾼 뒤 삭제해서 해결했습니다. Actions 실행 기록은 별도 API 로 지웠습니다. 기록을 지워도 배포된 사이트는 그대로 유지됩니다.

#### 제출 문서 정리

**(11) `.gitignore` 가 `.env.example` 까지 막고 있었음**

기존 규칙 `.env.*` 때문에 예시 파일까지 무시됐습니다. 예시 파일은 저장소에 있어야 다른 사람이 참고할 수 있으므로 `!.env.example` 한 줄을 추가해 예외로 뒀습니다. 기존 규칙은 그대로 두고 덧붙이기만 했습니다.

**(12) README 에 개인 컴퓨터 경로가 들어 있었음**

Windows 실행 안내에 `cd C:\Users\areum\git_ws\platen` 처럼 제 작업 폴더 경로가 그대로 적혀 있었습니다. 다른 사람은 실행할 수 없는 안내였습니다. "저장소를 받은 폴더로 이동"으로 바꾸고, 저장소 받기(clone)를 맨 앞으로 옮겼습니다. `py`·`npx` 대안, Python 설치와 PATH 안내, Git Bash 경로도 함께 고쳤습니다.

**(13) 보안 검사**

README·`.gitignore`·`.env.example` 을 손보기 전에 저장소 전체에서 API 키·토큰·비밀번호·개인키·이메일 패턴을 검사했습니다. 추적 중인 파일 9개에서 발견된 비밀값은 없었습니다. `.env.example` 의 변수 예시는 모두 주석 처리해 실제 값이 들어가지 않게 했습니다.

## 이 저장소는 수업용입니다

국민대학교 경영대학원 「AI에이전트실무」 7주차 실습 저장소입니다. 수강생이 이 저장소를 **fork** 하고, 자기 해석으로 **기능 하나**를 더해 **Pull Request** 를 보냅니다. 강사가 검토·병합하면 Actions 가 돌아 운영 사이트가 바뀝니다. 수업이 끝나도 저장소는 열려 있습니다.

### 하는 법 (요약)

1. fork 와 clone — 두 줄은 손으로
   ```bash
   gh repo fork dandacompany/platen --clone
   cd platen
   ```
2. 이 폴더에서 개발용 Hermes 프로필(쌤)을 띄운다
   ```bash
   hermes -p dev
   ```
3. 나머지는 쌤에게 자연어로. 브랜치 → 기능 하나 → 브라우저로 **내가** 확인 → 커밋 → 푸시 → PR
4. PR 제목은 `[01분반] 이름: 기능` 형식. 본문은 템플릿이 열린다

자세한 절차와 프롬프트는 수업 전용관의 7주차 실습 가이드에 있습니다.

### 규칙

- **한 PR 에 기능 하나.** 작게. 큰 아이디어는 PR 두 개로 나눈다.
- `index.html` **한 파일**을 유지한다. 외부 라이브러리·빌드 도구를 넣지 않는다 (Google Fonts 는 예외).
- 기존 기능이 그대로 되어야 한다: 타이핑과 자모 조합, 램프 슬라이더 세 개, 램프 켜고 끄기, 자동 타이핑, 리셋, 타자 소리.
- 토큰·API 키·개인 이메일을 넣지 않는다. PR check 가 걸러내지만 사람이 먼저 본다.
- 병합 여부는 강사가 정한다. 수업 중에는 5~8건만 라이브로 병합하고 나머지는 수업 뒤에 병합한다.

### 로컬에서 열기

`index.html` 을 브라우저로 열면 됩니다. 서버가 필요하면:

```bash
python3 -m http.server 8000
# http://localhost:8000
```

### 내 fork 를 원본 최신으로 맞추기

다른 사람의 PR 이 먼저 병합되면 내 브랜치가 낡습니다. 쌤에게 "upstream 최신으로 맞춰 줘" 라고 하면 아래를 합니다.

```bash
git fetch upstream
git rebase upstream/main
```

충돌이 나면 쌤과 같이 봅니다. 작업 중인 변경이 있으면 `git stash` 로 잠깐 치웠다가 `git stash pop` 으로 되돌립니다. rebase 로 역사가 바뀐 브랜치를 다시 올릴 때는 `git push --force-with-lease origin <내 브랜치>` 입니다 (내 브랜치에만).

## 배포

`main` 에 병합되면 `.github/workflows/deploy.yml` 이 저장소 루트를 GitHub Pages 에 올립니다. 1~2분 뒤 https://memo.dante-labs.com 이 바뀝니다. PR 이 열리면 `.github/workflows/pr-check.yml` 이 `index.html` 존재·형식·비밀값 패턴을 검사합니다.
